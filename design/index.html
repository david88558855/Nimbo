Nimbo
多协议网盘客户端

一个客户端，接入 FTP / SFTP / S3 / WebDAV 四类网络协议，外加本机与映射盘；每个挂载可单独指定 HTTP / SOCKS5 代理，互不影响。视觉沿用 OpenList-Client 的「浅蓝灰画布 + 天空青渐变 + 高密度紧字距」体系，在此之上重构为多协议挂载模型：挂载是容器，文件是内容，传输是常驻状态。

Design Principles

四条设计原则

所有取舍以此为准，评审时用它们判断对错，而不是凭喜好。

01

挂载即上下文

任何时刻界面都在回答「我在哪个存储的哪条路径」。挂载色标、协议徽标、地址栏三处同时锚定位置。

02

全协议同构

四类网络协议与本地盘共用一套行、详情、操作与状态。差异只出现在连接表单与能力差异提示里，不分裂为多套界面。

03

传输永远可见

桌面常驻底部抽屉 + 标题栏微型进度，移动端底栏徽标。离开传输页不丢失进度感知。

04

密度双档

同一套栅格，桌面行高 44、移动 66。信息密度跟随输入方式（指针 / 手指），而非跟随设备。

Design Language

设计语言

色彩、字阶、间距、圆角全部来自同一组 token，两端只是缩放不同。

色彩：蓝色只出现在「可操作」与「已选中」

中性蓝灰承担 95% 面积；天空青渐变仅用于主行动、进度条与品牌标识，单屏不超过 3 处，避免渐变贬值。协议色只用于 icon 与徽标底色，绝不作为正文颜色——保证色弱用户仍能通过文字识别。

只做这一套浅色主题，不提供深色与「跟随系统」切换。因此设计稿不再保留第二套调色板：一套 token 意味着对比度校验、截图回归、图标与插画资源只维护一份，深色模式的收益不足以抵消这部分长期成本。设置页也不再有「外观」分区。

字体：紧字距 + 大字号反差

系统字体优先（Windows 走 Segoe UI Variable，Android 走思源/系统字体），不打包字体文件。字号沿用参考项目的可读性修正：桌面 ×1.12、移动 ×1.30，均以 clamp 实现，不覆盖系统无障碍字号。

4pt 栅格

4 / 8 / 12 / 16 / 24 / 32。行高：桌面 44、移动 66；触控目标 ≥ 44。

圆角

桌面端：三栏 + 常驻传输

左导航 236、主区弹性、详情 320；底部抽屉 94 与状态栏 30 永远不参与滚动。

画板按容器宽度等比缩放（约 85%），放大浏览器即可查看 1:1 细节。桌面端的核心判断是「一次看到三件事」：我在哪（面包屑 + 挂载）、这里有什么（表格）、这个文件是什么（详情面板）。因此详情不做成弹窗，而是常驻第三栏，单击行即更新，双击才进入/预览。

1搜索即命令。同一入口既搜文件名，也接受 webdav 团队 这类命令与路径跳转，回车直达。
2挂载是身份。切换器常驻左上，切换即换根，旧任务的进度不会丢。
3计数可见。传输数直接标在导航上，用户不必点开才知道有任务在跑。
4单一主行动。一屏只有一个渐变按钮，其余为描边或幽灵按钮。
5列可读。表头 9px 全大写 + 字距 1px，与 12px 正文拉开层级，不靠加粗区分。
6选中 vs 悬停。选中用左侧 3px 竖条 + 淡蓝底；悬停只提亮，不改变结构。
7协议能力外显。只读、无容量、无原子移动等限制直接写在权限行，避免用户点了删除才发现失败。
8进度双通道。抽屉给细节，标题栏给总量；关闭抽屉仍有感知。
9状态栏是诊断入口。点击延迟数字可直接打开连接诊断。

Protocol Matrix

五类存储接入方案

同一套文件模型，五个驱动；SMB 已由「映射盘 + WebDAV / SFTP」替代。

v1.1 移除 SMB，第五类存储改为「本地与映射盘」 v1.2：单一浅色主题 · 代理按挂载独立
移除与不做的范围

不做 SMB / CIFS 实现，自研 SMB2/3 与 FFI 绑定 libsmb2 两条路线一并放弃；本版也不做 NFS 与各家网盘的 OAuth 授权，后续按需增补。

SMB 场景的三条替代路径

① 映射盘：Windows「映射网络驱动器」后按本地盘接入；② WebDAV：群晖 / 威联通 / TrueNAS 开启 WebDAV Server；③ SFTP：NAS 开启 SSH 走文件级访问。

预期效果与代价

P0 风险清零，依赖回到成熟 pub 包 + dart:io；NAS / 对象存储 / 团队盘 / 老 FTP / 本机中转全覆盖。代价：应用内不能直接浏览未映射的 SMB 共享。

五类存储映射到统一的 RemoteEntry（名称 / 路径 / 大小 / 修改时间 / 是否目录 / 校验值）与同一组操作。凡是协议做不到的事，界面不隐藏，而是降级并在按钮旁标注原因。

协议端口 / 安全认证 关键字段能力差异与界面提示

代理：一对一绑定到挂载，没有全局开关

有些存储只在特定网络可达——内网 NAS、需要跳板的机房、区域受限的对象存储。Nimbo 把代理做成挂载自己的属性，而不是应用级开关：A 挂载走代理、B 挂载直连，两条链路同时存在、互不影响；不读系统代理，也不改系统设置。

两条链路可以同时存在
SFTP家庭 NAS 直连 nas.home.lan:22
FTP老服务器 HTTP 127.0.0.1:7890 10.0.0.8:21

关掉代理只影响「老服务器」，家庭 NAS 的会话与传输不受任何影响；反之亦然。

作用域规则
写在挂载里：代理随挂载一起保存 / 编辑 / 删除，不进全局设置。 只作用于本挂载：该挂载的列表、上传、下载、预览共用同一条隧道。 即时生效：改完配置后新连接立刻走新链路，进行中的任务按新配置重试。 LOCAL 不提供代理：本地盘没有网络层，向导里该项自动隐藏。
字段说明
类型HTTP（CONNECT 隧道） / SOCKS5
主机 · 端口默认 127.0.0.1:7890，支持域名
认证用户名 / 密码可选，写入系统凭据库，不落配置文件

目标不可达 隧道已建立，但 10.0.0.8:21 无响应。请检查目标地址与端口。

「测试连接」分两段计时：先探代理 TCP 握手，再探目标；挂载卡片的连接日志按段记录，一眼看出是代理侧还是目标侧的问题。

实现上五个驱动共用一层 ProxyConnector：HTTP 走 CONNECT 隧道、SOCKS5 握手后透传；HTTP 类协议由 HttpClient 适配接管，FTP / SFTP 复用同一套 Socket 工厂——代理只在连接层实现一次，驱动本身不需要感知。

统一驱动抽象（下一阶段直接落地）

// 五个协议实现同一个接口，UI 层只依赖抽象
abstract class StorageDriver {
  String get scheme;                                  // ftp | sftp | s3 | webdav | local
  Capability get caps;                                // 能力位：move / copy / space / checksum / resume

  Future<List<RemoteEntry>> list(String path, {String? cursor});
  Future<RemoteStat> stat(String path);
  Future<Stream<List<int>>> read(String path, {int offset = 0});

  Future<void> write(String path, Stream<List<int>> data, {int offset = 0});
  Future<void> mkdir(String path);
  Future<void> rename(String from, String to);
  Future<void> remove(List<String> paths);
  Future<SpaceInfo?> space();                            // 不可查询时返回 null
}

上层只认 StorageDriver，因此「传输调度」「离线缓存」「批量操作」「详情面板」四套逻辑写一次即可覆盖五个协议；新协议只需补一个实现与一份表单描述。

三个必须先想清楚的技术点

RISK 01 · 最高优先
本地盘与映射盘的平台差异

Windows 侧路径稳定，映射盘符可直接读写；Android 侧受 Scoped Storage 限制，必须走 SAF 授权目录，且授权可能被系统回收。

授权失效时必须降级为「只读缓存 + 重新授权」引导，不能静默失败。

RISK 02
S3 没有原子移动

rename 只能 copy + delete。界面用「移动中」状态承接，失败时保留源对象并明确告知未删除，绝不出现「源没了、目标也没成」。

RISK 03
大文件吞吐

SFTP 窗口 32 MB、S3 分片 8 MB + 并发 4、WebDAV 复用长连接；传输层统一做令牌桶限速，避免五套驱动各写一套。
